3 GAPS MÁS GRANDES (por impacto)
═══════════════════════════════════════════════════════════════════════════════

🔴 GAP 1 — Scope selector + filtros RSVP
   Es el centro del handoff. Toda la navegación pivota sobre seleccionar
   "Soporte" vs "Evento X" y filtrar por estado RSVP.
   Requiere:
     · Refactor data model: vincular conversación → evento.
     · Endpoint backend GET /events del usuario.
     · UI dropdown scope (8-12 h).
     · Campo `guestStatus` en Conversation + RSVP CRUD (4-6 h backend).
     · Pills filtros + lógica filtrado cliente (3-4 h).
   Total estimado: 15-22 horas de trabajo (~3 jornadas).

🔴 GAP 2 — Sidebar derecho contextual (RSVP + asign + notas + historial)
   Requiere:
     · Extender layout chat-ia a 3 columnas (rail + left panel + main + right sidebar).
     · 4 sub-componentes: RSVPButtons, AssignPicker (con teams), NotesPanel, ContactTimeline.
     · 3 endpoints CRUD nuevos (RSVP, notes, teams).
     · Sync localStorage→backend para notas existentes.
   Total estimado: 12-18 horas (~2-3 jornadas).

🔴 GAP 3 — Sistema IA copilot/autopilot + draft cards
   Es funcionalidad nueva, no recambio. Requiere modelo conceptual completo:
     · Definir cómo IA genera borradores (¿en cliente? ¿api-ia? ¿streaming?).
     · Definir lógica autopilot (¿envía sin aprobar tras X tiempo?).
     · Componente DraftCard (Aprobar/Editar/Descartar).
     · Endpoints backend para draft + approval.
     · Storage de drafts pendientes.
   Total estimado: 20-30 horas (~3-4 jornadas).
