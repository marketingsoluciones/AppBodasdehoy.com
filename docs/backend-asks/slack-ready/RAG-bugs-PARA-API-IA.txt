BUG 2 (MEDIA) — /api/lobechat-kb/batch-embed contrato array vs objeto
────────────────────────────────────
Vuestro OpenAPI dice que /batch-embed espera un ARRAY [{text,user_id,file_id}].
chat-ia (rag.ts:73) envía un OBJETO {file_id, user_id} SIN text (solo dispara la tarea por file_id).

curl -X POST .../api/lobechat-kb/batch-embed -H "X-Development: bodasdehoy" \
  -d '{"file_id":"smoke-file-1","user_id":"smoke-test"}'
→ 422 "Input should be a valid list"

DECISIÓN DE CONTRATO (necesitamos vuestra postura):
 - Opción A: el FRONT manda el array de chunks ya con sus textos. Problema: el front NO tiene los
   textos de los chunks, solo el file_id (vosotros tenéis el archivo vía /files/*).
 - Opción B (recomendado COORD): /batch-embed recibe {file_id, user_id} y api-ia lee los chunks
   del archivo internamente y los vectoriza. El front solo dispara por file_id.
¿Confirmáis Opción B o preferís otra? Según vuestra respuesta, COORD alinea el front.
