🔴 CAUSA RAÍZ ENCONTRADA (auditoría SSH read-only de VUESTRO código, src/index-simple.ts:275-282):
   El flapping NO es por abrir demasiadas conexiones — es por config de pool DEMASIADO AGRESIVA:

     await mongoose.connect(mongoUri, {
       maxPoolSize: 2,            // ❌ solo 2 conexiones máx (multi-usuario → 3ª query falla/espera)
       minPoolSize: 0,            // ❌ CERO conexiones persistentes
       maxIdleTimeMS: 10000,      // ❌ cierra conexiones inactivas a los 10s
       ...
     });

   QUÉ PASA: tras 10s sin queries → minPoolSize:0 deja el pool VACÍO. Llega una query → Mongoose
   intenta usar el pool vacío → "Client must be connected"/MongoNotConnectedError ANTES de reconectar.
   ESO ES EL FLAPPING EXACTO. Además maxPoolSize:2 ahoga la concurrencia multi-tenant.
   El comentario del código dice "para evitar exceder límites" → fue una optimización para el M0 que
   CAUSÓ el problema. Y PM2 muestra ↺30 reinicios en 8min (crash loop) — síntoma del mismo problema.

   OJO: hay DOS configs de pool en el repo — index-simple.ts (max2/min0, ACTIVA) vs
   conector-fix.ts (max10/min2). La activa es la mala.
