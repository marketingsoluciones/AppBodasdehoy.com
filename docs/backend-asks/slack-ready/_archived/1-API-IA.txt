1) ENDPOINTS NUEVOS — servicio `thread`
----------------------------------------

`thread` es el único servicio chat-ia sin cobertura en vuestro openapi.json (0 endpoints). Sigue el patrón de /chat/topics y /chat/messages que ya existen.

Modelo Thread (tomado del schema drizzle actual del front):

  id:              string (pk)
  title:           string | null
  type:            'continuation' | 'standalone'        (NOT NULL)
  status:          'active' | 'deprecated' | 'archived' (default 'active')
  topicId:         string FK → topics.id, cascade       (NOT NULL)
  sourceMessageId: string                                (NOT NULL)
  parentThreadId:  string | null  FK → threads.id (set null)
  userId:          string (resolver del JWT)
  createdAt:       datetime
  updatedAt:       datetime

Endpoints solicitados (6):

  GET    /chat/topics/{topic_id}/threads
         → 200 [Thread, ...]
         Lista threads del topic, filtrado por userId del JWT.

  POST   /chat/topics/{topic_id}/threads
         body: { title?, type, sourceMessageId, parentThreadId? }
         → 200 Thread

  PATCH  /chat/threads/{thread_id}
         body partial: { title?, type?, status?, parentThreadId? }
         → 200 Thread

  DELETE /chat/threads/{thread_id}?removeChildren=true|false
         → 204
         Si removeChildren=true, borra recursivo. Default false.

  POST   /chat/topics/{topic_id}/threads/with-message
         body: { title?, type, sourceMessageId, parentThreadId?, message: CreateMessageParams }
         → 200 { threadId, messageId }
         Crea thread + primer mensaje atómicamente (transacción).

  DELETE /chat/topics/{topic_id}/threads
         → 204
         Borra TODOS los threads del topic (usado al borrar topic).

Auth: idéntica a /chat/topics existente — Authorization: Bearer <JWT> + X-Development.

3.2) Duplicación user-config
     Existen GET /api/auth/get-user-config y POST /api/auth/save-user-config.
     services/global.ts espera config global, services/user/server.ts espera config de usuario.

     ¿Misma tabla / mismo endpoint, o son fuentes distintas?

3.3) plugin vs tool

     Body actual front: { identifier, action, params }

     ¿Hay un campo kind: 'tool' | 'plugin' esperado? ¿O se deduce por identifier?

3.4) image — endpoint canonical para CRUD

     ¿Cuál es el canonical?
     - ¿/api/storage/r2/files (GET con filter por id)?
     - ¿O hay /api/images dedicado no listado en openapi?
     - ¿O lo construimos sobre /api/storage/files/{file_id}?

3.5) upload — flujo recomendado

     - Upload de archivo arrastrado al chat (attachment de un mensaje)
     - Upload de archivo a knowledge base
     - Upload de avatar/imagen de usuario
