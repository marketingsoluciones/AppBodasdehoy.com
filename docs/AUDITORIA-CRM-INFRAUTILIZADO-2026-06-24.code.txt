BUG BACKEND DETECTADO (PARA REPORTAR A api-mcp)
═══════════════════════════════════════════════════════════════════════════════

DESALINEAMIENTO SDL público vs schema Mongo real (descubierto SSH):

  SDL GraphQL (publicado):
    enum CRM_NoteEntityType {
      CONTACT, LEAD, OPPORTUNITY, EVENTO, ENTITY,
      CAMPAIGN, TASK, CONVERSATION  ← presente en SDL
    }

  Mongo Schema (real en BD, dist-production/src/db/models/note.js):
    enum: ["CONTACT", "LEAD", "OPPORTUNITY", "EVENTO",
           "ENTITY", "CAMPAIGN", "TASK"]
                                                ↑ FALTA CONVERSATION

  IMPACTO:
    Si el front intenta createCRMNote con entityType: CONVERSATION:
      · GraphQL valida OK (está en el SDL).
      · Mongo rechaza por enum constraint.
      · Error opaco al user.

  WORKAROUND mientras lo arreglan:
    · Para conv huérfana sin contact: usar entityType: ENTITY con
      entityId: conversationId (ENTITY es el catch-all genérico).
