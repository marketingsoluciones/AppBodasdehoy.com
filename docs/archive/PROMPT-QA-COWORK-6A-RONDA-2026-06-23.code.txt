🆕 BLOQUE E — BUGS PENDIENTES DEL BACKLOG (commit 211a2b4b)
───────────────────────────────────────────────────────────────────────────────

  BUG-CW-N04 ✅ Hydration #418 en /login (chat-dev)
  ─────────────────────────────────────────────────────────
  Archivo: apps/chat-ia/src/app/[variants]/(auth)/login/[[...login]]/_page-client.tsx
  Causa raíz:
    `useSearchParams().get('reason')` devuelve valor DISTINTO entre SSR
    (vacío en prerender estático) y CSR (real con ?reason=session_expired).
    El render condicional `sessionExpiredMessage={reason === ... ? ... : null}`
    en LoginForm causaba mismatch → React #418.
  Fix:
    Guard `mounted` flag — `reasonAfterMount = mounted ? reason : null`.
    Primera pasada CSR (igual que SSR) usa null; segunda pasada
    (post-useEffect) usa el valor real. Sin mismatch.
  PROBAR:
    1. Cerrar sesión.
    2. Visitar chat-dev.bodasdehoy.com/login?reason=session_expired
    3. Abrir DevTools Console — NO debe aparecer error #418 ni
       "Hydration failed because the initial UI does not match...".
    4. El mensaje "Tu sesión ha expirado..." debe aparecer (tras hidratar).

  BUG-CW-N12 ✅ Tool router silencioso si Render falta (chat-dev)
  ─────────────────────────────────────────────────────────
  Archivo: apps/chat-ia/src/features/PluginsUI/Render/BuiltinType/index.tsx
  Causa raíz:
    Cuando la IA invocaba una tool con identifier NO registrado en
    `BuiltinToolsRenders`, el componente devolvía undefined silenciosamente
    (`if (!Render) return;`). Bugs reales (identifier mal en api-ia, tool
    nueva sin registrar) quedaban invisibles.
  Fix:
    Console.warn explícito en dev con identifier + apiName. En prod sigue
    retornando silencioso. Esto solo EXPONE bugs; el fix real (si aparece
    un warn) debe ir en api-ia o en src/tools/renders.ts según corresponda.
  PROBAR:
    1. chat-dev con DevTools Console abierta.
    2. Invocar al chat: "muéstrame un análisis del presupuesto" o similar
       que dispare tools.
    3. Si alguna tool no renderiza, debe aparecer warn:
       [BuiltinType] No render registered for identifier="X" (apiName="Y").
    4. Si TODAS renderizan bien, NO debe aparecer warn (test de no-regresión).

  BUG-CW-N13 ✅ Race condition $evento_id en Invitaciones (app-dev)
  ─────────────────────────────────────────────────────────
  Archivo: apps/appEventos/pages/invitaciones.tsx
  Causa raíz:
    useEffect lanzaba 3 queries GraphQL con `evento_id: event?._id` sin
    guard. Si el componente montaba antes de que EventContextProvider
    hidratara el evento activo, los queries iban con evento_id=undefined →
    backend respondía vacío o error → race visible en UI.
  Fix:
    Guard `if (!event?._id) return;` al inicio del useEffect, antes de
    cualquier fetch. Las 3 queries ahora SIEMPRE tienen evento_id válido.
  PROBAR:
    1. Login + seleccionar evento ("Boda Isabel & Raúl").
    2. Ir directamente a /invitaciones desde URL (sin pasar por home).
    3. DevTools Network → filtrar GraphQL.
    4. NO debe aparecer ningún POST con `evento_id: null` o
       `evento_id: undefined` en variables.
    5. La página debe renderizar templates correctamente (no spinners
       infinitos, no errores en consola).
