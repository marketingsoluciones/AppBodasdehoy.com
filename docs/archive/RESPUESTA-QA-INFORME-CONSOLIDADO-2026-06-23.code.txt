BUG-CW-N22 (que reportasteis como nuevo) — Logo abre www.bodasdehoy.com producción
  ──────────────────────────────────────────────────────────
  CONFIRMACIÓN: tenéis razón. El fix anterior de N20 (commit 4887975f)
  tocó el LOGO de NavigationMobile (el bottom-nav con 5 botones),
  pero este es OTRO logo distinto — el del header superior
  (apps/appEventos/components/DefaultLayout/Navigation.tsx).
  Bug separado, no regresión.

  Causa raíz: en whitelabel `bodasdehoy`, `config.pathDomain` viene como
  "https://www.bodasdehoy.com". El onClick hacía `window.open(path, '_blank')`
  cuando path empezaba por http(s) → sacaba al usuario de app-dev.

  Fix aplicado: si pathDomain apunta al mismo origin → router.push interno.
  Si apunta a otro origin (producción/tenant distinto) → router.push("/")
  al home de la app actual. NUNCA window.open externo desde el logo.

BUG-CW-N21 (que reportasteis como nuevo) — Modal presupuesto oculto bajo navbar
  ──────────────────────────────────────────────────────────
  Archivo: apps/appEventos/components/Presupuesto/PresupuestoInitModal.tsx

  Causa raíz: el modal usaba `items-center justify-center` sin
  `overflow-y-auto`. En viewports donde la altura del modal excede la
  del viewport (~880px de alto desktop, mobile vertical), el contenido
  superior (header con título y X) quedaba fuera de pantalla y tapado
  por la navbar sticky. Además z-50 colisionaba con menús laterales
  que también usan z-50, dejando ambigüedad de stacking.

  Fix aplicado:
    · z-[60] (por encima de menús z-50 y de la navbar).
    · items-start en mobile, items-center desde sm: en adelante.
    · overflow-y-auto + py-8: si el modal es más alto que el viewport,
      scrollea internamente y mantiene la X siempre alcanzable.
    · my-auto en el contenido para mantener centrado cuando cabe.

  REPROBAR:
    1. Viewport 880px desktop, /presupuesto en evento sin categorías.
    2. Modal "¿Cómo quieres empezar?" debe aparecer con la X visible
       arriba a la derecha (sin solapar navbar).
    3. Click backdrop, Escape, y click en X deben todos cerrar.
    4. Cambiar viewport a 390px (mobile) — modal debe seguir accesible,
       con scroll interno si su altura excede el viewport.

(2) BUG-CW-N06 — borrarGasto NO falla en la UI real
  ──────────────────────────────────────────────────────────
  Reportasteis: "borrarGasto NOT IN schema, proxy-bodas/graphql → 400"

  Investigación: el fix N06 que apliqué (commit 56cdb596) cambió
  `borraGasto`→`borrarGasto` en apps/appEventos/utils/Fetching.ts (línea
  1468). PERO en `apps/appEventos/utils/apiMcpAdapter.ts:120` hay un
  ADAPTER que intercepta esa mutation:

    borrarGasto: {
      canonicalQuery: `mutation(...) {
        eliminarGastoPresupuesto(...) { ... }   // ← nombre REAL en api-mcp
      }`,
      mapVariables: (v) => ({ evento_id, categoria_id, gasto_id }),
      mapResponse: (p) => presupuestoSuperset(p),
    }

  Flujo real al borrar un gasto desde la UI:
    UI → fetchApiEventos({ query: queries.borrarGasto }) →
    extractGraphqlField(query) detecta "borrarGasto" →
    MCP_ADAPTERS["borrarGasto"] EXISTE →
    fetchApiBodas con el canonicalQuery (eliminarGastoPresupuesto) →
    api-mcp resuelve, devuelve presupuesto actualizado → OK ✅

  Vuestro test directo a `/api/proxy-bodas/graphql` con mutation
  `borrarGasto` falla a propósito — ese endpoint legacy NO tiene la
  mutation porque su nombre canonical en api-mcp es
  `eliminarGastoPresupuesto`. Sin pasar por el adapter, no se traduce.

  PROCEDIMIENTO CORRECTO para validar N06:
    1. Login + entrar a /presupuesto del evento "Boda Isabel & Raúl".
    2. Asegurar que hay al menos 1 categoría con al menos 1 gasto.
    3. En la UI, borrar el gasto desde el botón ×/papelera.
    4. DevTools Network → buscar el POST GraphQL.
       Debe ir a /api/proxy-bodas/graphql con query
       `eliminarGastoPresupuesto` (NO `borrarGasto`).
    5. Response debe ser 200 con `success: true`.
    6. El gasto desaparece de la UI sin errores en consola.

  CONCLUSIÓN: N06 está RESUELTO en la UI. El "fail" del test directo
  contra el endpoint no representa el flujo real del producto.
