## 5. Cómo funciona el auth end-to-end

- **Login directo app-dev:** Firebase → `mutation auth(idToken)` en api-mcp → `sessionBodas`.
- **Login directo chat-dev:** Firebase → api-ia `firebase-login` → `mcp_jwt` + **también** `callMcpAuthMutation` → `sessionBodas` (para SSO chat→app).

## 7. Gotchas conocidos (rompen fácil)

1. **`packages/auth-ui/dist/` NO se regenera solo.** El build script del portátil ya lo hace en `step_shared` desde el 2-jul. Si compilas local sin ese step, cambios en `LoginForm.tsx` no llegan al bundle appEventos.

2. **`main worktree` puede tener ramas distintas a `.worktrees/dev-promote`.** El main a veces está en `hotfix/...` o `tj/refactor/...`. Antes de hacer cualquier commit desde main, `git branch --show-current`.

3. **`git restore <spec>` en main worktree revierte a HEAD de la rama actual**, no a origin/dev. Si tienes cambios locales al spec y estás en una rama antigua, los perdiste.

4. **`e2e-app/smoke-qa-r6-gaps.spec.ts`** puede tener versiones distintas en main vs dev-promote. **La versión canónica está en `origin/dev`.** El main puede tener versión reducida.

5. **`window.__authDegraded`** aparece en dev-console cuando Firebase auth OK pero backend api-mcp no devuelve `sessionCookie`. Es visible como chip `deg` amarillo en el DebugFooter. NO es un crash, es warning de estado degradado.

6. **`AbortSignal.timeout(N)`** en el helper `mcpAuth.ts` — si el backend tarda más, el error NO se propaga como GraphQL, se propaga como `AbortError`. El caller ya lo captura con try/catch.

7. **`dev-user-config`** en LocalStorage es lo que Lobe/chat-ia usa para saber "quién soy". Si `token` field está null pero `userId` existe, chat-ia dice "Usuario identificado pero sin JWT válido". Es transitorio ~500ms tras login.
