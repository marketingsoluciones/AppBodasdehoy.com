OBJETIVO
────────
El user pide eliminar runtimeMap + 66 providers + SDK deps (Ollama, OpenAI direct,
Anthropic, Google, etc.) porque api-ia centraliza modelos (auto-route + modelo-fijo).

HALLAZGOS — usos REALES de model-runtime
─────────────────────────────────────────

1) /webapi/chat/[provider]/route.ts  ✅ YA NO USA runtimeMap
   Es proxy puro a `resolveServerBackendOrigin()` = api-ia.
   El chat streaming en producción NO toca runtimeMap.

2) /webapi/chat/azureai/route.ts     → revisar (un solo provider hardcoded)

3) tRPC lambda router — aiChat (`lambdaClient.aiChat.*`)
   • generateObject       — usado por services/aiChat.ts:generateJSON (output estructurado)
   • sendMessageInServer  — usado por services/aiChat.ts:sendMessageInServer (envío async)
   Ambos llaman `initModelRuntimeWithUserPayload(provider, payload)` → toca SDKs.

4) tRPC lambda router — image (`lambdaClient.image.*`)
   ✅ ELIMINADO del cliente. Comentario en services/image.ts:4 lo confirma.

5) tRPC lambda router — file (`lambdaClient.file.*`)
   Embeddings RAG: pMap → initModelRuntimeWithUserPayload(provider, ctx.jwtPayload)
                  → agentRuntime.embeddings({dimensions, input, model})
   Es Postgres embeddings (alternativa Pinecone/Qdrant); ruta caliente con docs subidos.

6) tRPC async router — ragEval (`asyncClient.ragEval.*`)
   Idem RAG eval — usa runtime.

7) tRPC async router — image
   Generación imágenes (DALL-E 3, BFL, etc.). Usado por sliderImageBlock y similar.
